# 智策台 DecisionDesk — 功能需求

## 功能清单

### Must Have（必须）
- F-001：股票输入与识别 — 支持代码、名称、自然语言输入，并进行标的映射与确认。
- F-002：单股自动分析 — 确认标的后直接启动完整分析。
- F-003：官方投研团队协作 — 通过 Multica 调度固定官方 Codex Agent 团队完成角色化分析与裁决。
- F-004：结果页主状态卡 — 展示五段推荐状态、操作建议、目标价、止损位、建议仓位、时间信息。
- F-005：结构化投研报告 — 输出图表化决策报告与本地 HTML 文件。
- F-006：自选股列表 — 展示股票名、当前价、五段状态、最近更新时间。
- F-007：定时重评估 — 默认收盘后自动更新，支持更多频率供用户配置。
- F-008：多股对比 — 自然语言生成候选池，用户删改后对最多 5 只股票进行对比。
- F-009：任务历史 — 历史任务按时间倒序列出。
- F-010：重新分析 — 结果页顶部固定按钮，触发新任务版本。

### Should Have（应该）
- F-011：准实时行情 — 仅用于自选股列表和结果页顶部状态卡。
- F-012：轻量持仓录入 — 支持是否持仓、成本价、仓位/股数。
- F-013：通知代理 — 支持桌面通知、应用内消息与 openclaw / hermes 风格代理通道。
- F-014：双语界面与双语报告 — 中文 / 英文切换，报告跟随界面语言。

### Could Have（可以）
- F-020：候选池主题理解增强
- F-021：更多分析频率配置模板

### Won't Have（不做）
- F-030：用户自由组队
- F-031：账号必需与云同步
- F-032：首版暗色模式

## 业务规则与逻辑
- BR-001：五段推荐状态绑定默认操作语义。
- BR-002：任务状态最小集合为排队中、分析中、已完成、失败。
- BR-003：每次重新分析都生成独立历史任务，不覆盖旧结果。
- BR-004：状态每次重评估都重算；仅在阈值变化或关键事件命中时主动通知。
- BR-005：多股对比先统一综合评分，再由风险裁决层给出首选建议。
- BR-006：官方投研团队为平台固定团队，用户仅可查看角色与状态，不可编辑团队结构。
- BR-007：分析任务的实际执行单元为 Multica Issue；DecisionDesk 负责创建、订阅和渲染结果。

## 数据模型与实体关系
- 实体：Task、Issue、Stock、WatchItem、Report、Team、Role、NotificationRule、HoldingProfile、AnalysisResult
- 关系：Task 可拆分为多个 Multica Issue；Task 关联一个或多个 Stock；Task 消费一个 AnalysisResult 并产出一个 Report；WatchItem 绑定 Stock 与更新策略。

## API 契约
- DecisionDesk 通过 Multica API 创建父 Issue 与子 Issue，并通过 WebSocket 订阅进度。
- Codex Agents 基于内置模型通道、市场数据源与联网检索完成分析，统一回传 AnalysisResult JSON。
- 输入需包含市场标识、股票代码、用户原始问题、语言偏好、可选持仓信息。
- AnalysisResult 至少包含：推荐状态、操作建议、关键价格位、四维评分、多空辩论、风险裁决、关键事件、来源摘要、生成时间、更新时间。

## 状态机与流程图
- 输入 → 标的识别 → 候选确认 → 排队中 → 分析中 → 已完成 / 失败
- 已完成结果可触发：加入自选、重新分析、导出 HTML、本地打开
- 执行链路：DecisionDesk 创建分析任务 → Multica 分发子 Issue → Codex Agents 产出 AnalysisResult → DecisionDesk 渲染结果页与 HTML 报告
